## North-Star Invariant (the constitution)

**At a fixed `contrib_floor`, every correct culling implementation must
produce the same image, modulo floating-point accumulation-order noise.**

Concretely:
- A `(Gaussian, microblock)` pair is *visible* iff `max over pixels in
  microblock of (opacity · exp(-½·m²)) ≥ contrib_floor`.
- Anything below `contrib_floor` is irrelevant by definition.
- Any cull that drops a visible pair is a **bug**. Any cull that admits
  an invisible pair is fine but wasteful.
- **PSNR vs the reference render at the same `contrib_floor` must be
  ≥ 60 dB.** Below that = algorithm regression, not perf regression.

This invariant is what the entire TDD pyramid checks, top to bottom.

## The Three Render Paths

| Path | Language | Purpose | Speed (target) |
|---|---|---|---|
| `cpu-ref` | numpy | Bit-truth spec; the algorithm definition | Slow, doesn't matter |
| `cpu` | C++ | Perf vehicle, std::thread pool, 30-frame benchmark | Interactive (sum of 30 < 1 s ideal) |
| `tt` | metal | Eventual port, one stage at a time | Deferred until `cpu` is optimal |

`cpu-ref` never goes away. It is how we verify each `cpu` iter is faithful.

## 30-Frame Training-Pattern Benchmark

Structure (seeded so reproducible — `numpy.random.default_rng(0)`):
- 1 hero (the canonical pose from benchmarks/cameras.json)
- 5 hero-adjacent (small camera jitter ≈ training augmentation)
- 12 orbit (every 30° at hero elevation)
- 6 elevation (±15° pitch increments)
- 6 challenge (top, bottom, very close, very far, two side-occluded)

**Sort by camera-position proximity (greedy nearest-next) before
benching.** No coherency-by-scenario measurement; the sort gives natural
frame-coherency wins where available and a true worst-case run otherwise.

**Primary metric: sum of 30 wall-clock ms.** Reported with per-view-class
subtotals so we can see where coherency reuse kicks in vs. doesn't.

## TDD Pyramid

### Layer 1 — C++ unit tests (Catch2, ctest -j on every build)
Pin every primitive with deterministic inputs and expected outputs.
- Math kernels: quaternion→rotation, build_covariance_3d, Jacobian, Σ_2D, det+inverse, Mahalanobis quadratic form
- Geometry: closest-point-in-rect, AABB intersection
- Per-stage I/O contracts: project, tile_assign, per_pair_cull, per_microblock_cull, sort_and_bin, blend_single_tile
- Thread pool: N tasks all execute exactly once, no races
- Microblock cull correctness: for a hand-crafted Gaussian + tile, mask matches the analytic mask byte-for-byte

Each unit test loads its fixture from tests/fixtures/*.bin written by Phase 1.

### Layer 2 — numpy spec tests (pytest, on every iter)
- cpu-ref reproduces reference_v2/ to PSNR ≥ 80 dB (PNG roundtrip floor)
- Every numpy stage's output equals the corresponding fixture .bin
- Every algorithm change keeps the contrib_floor invariant: PSNR > 60 dB vs reference

### Layer 3 — visual reference tests (per iter, via validator subagent)
- 30-frame benchmark renders captured
- PSNR ≥ 60 dB on hero/side/top vs reference_v2/stitch_{hero,side,top}.png at contrib_floor=1/255
- diff10 cross-check (the existing 8-check visual validator carries over)

**Any iter failing Layer 1 doesn't make it to Layer 2. Any iter failing Layer 2 doesn't make it to Layer 3.**

## Iter Loop (supervisor execution)

```
for iter in [000, 001, 002, ...]:
    1. write prompts/worker-iter-NNN.md (filled-in from prompts/worker.md template)
    2. dispatch worker subagent (Composer 2.5) → implements change, runs ctest, writes
       metrics.json + 30 PNGs + timing.jsonl into opt/screenshots/iter-NNN-slug/
    3. dispatch validator subagent (Sonnet 4.6, fresh ctx) → reads artifacts only,
       writes validator.json with KEEP/REJECT/NEEDS_REVIEW
    4. scripts/decide_and_log.py → appends iters.jsonl, regenerates REPORT.html,
       commits or backburners
    5. supervisor picks next iter based on results + planned roadmap
```

Halt conditions: 30-frame sum < 1000 ms, OR clear physical lower bound reached
(measured by profiling), OR user interrupt.
