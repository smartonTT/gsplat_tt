## Recommended lever family (heuristic)

- blend kernel is `host-dominated`: the `device_fw_max` is  46.27 ms vs host wall  96.70 ms. Host-side lever family: batched upload, persistent inputs, Trace API, 2-CQ pipeline, smaller per-frame DRAM payloads. Device-side levers still independently valid — `device_fw_max` is itself a real floor that compounds with any host wins. Per-RISC table above identifies the dominant RISC; pursue both in parallel if zone data justifies it.
- `sort` is  65.42 ms =  20.2% of total. Current implementation is CPU torch.argsort; if it dominates, the win is moving sort to device or to a specialized radix on CPU.

_All numbers are medians over the measured cycles. The verdict above is a heuristic starting point — confirm with the per-RISC + sub-stage tables before committing to an iter plan._
